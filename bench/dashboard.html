Move pipeline

Server-side stages measured per move; per-recipient WebSocket write measured separately.

The waterfall is a typical move: request received → submitted → worker queue → engine → commit → broadcaster → recipient lookup → encode → outbox. The largest term is usually broadcast wait, the gap between the worker committing and the move handler reaching flush_through. That gap is the cost of batching and response-path scheduling, not recipient lookup.
